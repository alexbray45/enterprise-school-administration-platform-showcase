# ⚙️ Engineering Process

## Overview

AdminTrack was developed using a structured software engineering approach rather than beginning directly with implementation.

The project followed a phased development process that emphasised understanding the business problem, defining clear requirements, designing a maintainable architecture, and planning the implementation before writing code.

This approach helps reduce project risk, improves software quality, and ensures the solution aligns with business objectives.

---

# Software Development Approach

The project follows a phased Software Development Life Cycle (SDLC), where each stage builds upon the outcomes of the previous one.

```text

        │

UI/UX Design
        │
        ▼

```

# Phase 1 — Business Analysis

The project began by analysing the existing attendance administration process to identify operational challenges and opportunities for improvement.

Key activities included:

- Understanding existing workflows
- Identifying business problems
- Defining project objectives
- Identifying stakeholders
- Defining project scope

**Deliverable:**

- Business Analysis Document

---

# Phase 2 — Requirements Engineering

Once the business problem had been defined, system requirements were identified and organised.

This phase established what the system should accomplish while considering both functional and quality requirements.

Key activities included:

- Functional requirements
- Non-functional requirements
- Scope definition
- Constraints
- Assumptions
- Success criteria

**Deliverable:**

- Requirements Specification

---

# Phase 3 — System Design

The solution was then translated into a technical design that provides a blueprint for implementation.

Key design activities included:

- Selecting an architectural pattern
- Designing system modules
- Defining data flow
- Planning system interactions
- Selecting technologies

**Deliverable:**

- Architecture Documentation

---

# Phase 4 — UI/UX Design

Before development, the user interface was designed to support efficient administrative workflows.

The focus was on creating an intuitive experience that reduces repetitive tasks and improves usability.

Key activities included:

- User flow design
- Wireframing
- High-fidelity mock-ups
- Navigation planning
- Interface consistency

**Deliverable:**

- UI/UX Design Documentation

---

# Phase 5 — Development

With planning complete, implementation began using the documented requirements and design decisions as a guide.

Development follows modular engineering practices to improve maintainability and readability.

Current technologies include:

- React
- ASP.NET Core Web API
- Entity Framework Core
- PostgreSQL

**Status:** 🚧 In Progress

---

# Engineering Principles

The project is guided by several software engineering principles.

- Understand the problem before designing the solution.
- Separate business logic from presentation.
- Design for maintainability and scalability.
- Keep the architecture modular and extensible.
- Prioritise simplicity where appropriate.
- Document decisions throughout the development lifecycle.

These principles help create software that is easier to understand, maintain, and extend over time.

---

# Conclusion

AdminTrack demonstrates the value of following a structured software engineering process.

By progressing through analysis, requirements engineering, architecture, design, and planned implementation in a deliberate manner, the project establishes a solid foundation for building a maintainable, scalable, and reliable enterprise application.

Rather than viewing documentation as a separate task, it has been treated as an integral part of the engineering process, ensuring that design decisions remain clear, traceable, and aligned with the project's objectives.
